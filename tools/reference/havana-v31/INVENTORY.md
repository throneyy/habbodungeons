# Havana V31 static web content — stylesheet inventory

Local reference copy of the `www` tree served by
[Quackster/Havana](https://github.com/Quackster/Havana), a Habbo V31 server
emulator. This is the **static content only** — the CSS and images its `.tpl`
markup consumes. The `.tpl` files themselves live in the Havana server repo and
are **not** in this archive.

**The art and stylesheets are Sulake's copyright and are never committed.**
`.gitignore` tracks only this file and the survey script; the 37,213 extracted
files stay local. Verified: `git status` reports zero untracked paths here.

## Scope of this survey

**63 stylesheets, 23,948 selectors.** Everything below is generated by
`survey-css.py` in this directory:

```bash
python tools/reference/havana-v31/survey-css.py            # the tables
python tools/reference/havana-v31/survey-css.py --assets   # + url() resolution
python tools/reference/havana-v31/survey-css.py --json out.json
```

Two definitions, because both are easy to get wrong:

- A **family** is the first hyphen/underscore-delimited token of a class name
  (`habblet-header` → `habblet`, `myhabbo_note` → `myhabbo`). These sheets have
  no formal namespace; that prefix is the de-facto one. A single-token class is
  its own family, which is honest — it really is a one-off, not a system.
- A **selector count** counts *selectors*, not distinct class names:
  `.box, .box-tabs td` is two. That is the number worth knowing when judging how
  much CSS a family actually is. Comments are stripped first, since these files
  carry a lot of commented-out rules.

**Nothing has been copied into `hub/css`.** This is a map, not a migration.

## What is actually worth looking at

Of the 63 sheets, far fewer are useful reference:

- **`web-gallery/v2/styles/style.css`** (952 selectors, 297 classes) and
  **`web-gallery/static/styles/common.css`** (1,098 selectors, 338 classes) are
  the gallery's core. They are **near-duplicates**: 250 of their classes are
  shared, 47 unique to v2, 88 unique to common. Treat them as one system with
  two snapshots, not two systems — and diff before trusting either alone.
- **`box`** is the largest family in both (109 selectors each). It is the
  Habbo panel: `box-content`, `box-tabs`, `box-tabs-container`, `tab-spacer`,
  with per-theme variants driven by an ancestor class (`div.blue`, `div.green`,
  `div.red`, `div.gray`) repositioning one shared sprite sheet
  (`v2/images/inner-tabs.png`). That sprite-offset-per-theme approach is the
  closest prior art to our own `hw-*` window chrome.
- **`habblet`** (49–52 selectors) is the widget container: `habblet-container`,
  `habblet-list`, `habblet-button-row`, `habblet-close`.
- **`dialog`** (43 selectors in `common.css`, 42 in `v2/styles/boxes.css`) is
  the modal/rounded-corner system, built from corner GIFs in `images/dialogs/`.
- **`public/`** is **not Habbo**. It is Havana's own admin/CMS UI, written much
  later against Bootstrap — `bootstrap.min.css` alone is 3,129 selectors of
  vendor code and is noise for our purposes.
- **`myhabbo/assets.css`** (4,346 selectors, 3,930 classes) is a **generated
  sprite table**, not a component system: 3,372 of its selectors are in the `s`
  family (`.s-123` sprite offsets). Do not read it as design vocabulary.

## Asset resolution

Of 1,108 `url()` references across all sheets, **645 resolve and 463 do not**.
The gaps are concentrated in the legacy trees. For the two core sheets plus the
rest of `v2/styles/` and `static/` — 24 sheets — it is **392 resolved, 69
missing**, and the misses are mostly one directory: `v2/images/dialogs/*` corner
slices and a few icon sheets.

This mirrors the `habbo-2006` scrape's problem but is **not** the same failure:
here the files were simply never in the server's `www` tree, so there is nothing
to re-fetch. Any component rebuilt from `boxes.css` will need its corner art
sourced elsewhere or redrawn.
